主窗口的三个裁切入口改为控制器转发。它仍负责装配窄接口和兼容旧功能，不再包含裁切输出组装及后台计算实现。

### 提交与恢复语义

1. 预览只读输入；worker 不捕获主窗口或控制器，不访问场景容器和 VTK/Qt 界面对象。
2. 任务先核对取消状态，再交付 GUI；失败或取消都不能生成可应用结果。
3. 接收预览时核对会话票号、场景世代、源对象身份及输入缓冲区；应用前继续核对显示属性。
4. 先准备全部输出、检查名称/ID 冲突并构造目标容器，随后一次保存历史并发布模型；准备失败不修改当前场景。
5. 源对象与输出使用不同 ID；撤销恢复原 ID，重做恢复同一输出 ID。全局世代只前进，不随撤销倒退。
6. 裁切应用、撤销和重做保留相机；旧入口历史的相机策略继续沿用原行为。
7. 预览和热图临时隐藏不写入业务可见性。裁切临时隐藏及共享展示的隐藏状态通过只读查询还原为逻辑属性。
8. “分成两份”的两份输出均保留原矩阵、透明度、点大小和可拾取性；框外部分沿用原橙色约定。

点云快照共享数据，不为每条历史深复制整份点云。现有二十条历史上限保留，新增的 `retainedBytes()` 按唯一缓冲区 capacity 估算点数据保留量；该值不是进程 RSS，也尚未用于自动按字节淘汰历史。

## 验证

本次仅运行裁切相关程序及本试点新增的契约检查，没有运行凹塘、焊前装配、测距或其他功能回归。

- 修改前桌面基线：`build/clip_pilot_baseline.log`，`pass=65 fail=0`。
- 新场景/历史/任务契约程序：`analysis/polygon_clip/test_clip_contracts.cpp`，不链接主窗口，不访问私有成员。
- 扩充裁切桌面验证：`analysis/polygon_clip/test_polygon_clip.cpp`，通过菜单、按钮、鼠标事件和公开场景快照验证，不使用 `-fno-access-control`。
- 同请求数值对照使用工具公开的 `request()`，直接调用未修改的 `CloudClipper::compute()`；逐位比较输出 XYZ 和点序，不放宽容差。另保留旧射线法的内外点顺序对照及二百万点精确分区检查。
- 任务检查覆盖异常、预先取消、计算结束与取消竞争、关闭等待；控制器检查覆盖世代变化、同名不同 ID、输入替换、显示属性变化、迟到结果和拒绝提交。
- 初期桌面测试错误地把 PCL 坐标轴 LOD actor 当成原点云，导致参考变换错误及后续可见性断言失败。已按输入点数识别真正点云 actor，并使用工具实际捕获的同一请求核对；现在非默认矩阵/透明度等设置确实作用于原点云。初次日志保留，不修改算法或放宽比较条件。

## 边界与后续

- 本轮完成的是裁切纵向链路。其他功能仍经旧入口运行；未将其他功能迁移到新的 TaskRunner。
- 场景外观仍以旧 maps/actor 为存储来源；身份索引不另存颜色或显示属性。尚未建立全项目唯一记录仓库，不能宣称已经完成全部场景改革。
- 只读快照不能消除旧调用者持有的可写别名。当前通过计算期间禁止场景编辑和裁切算法只读输入保证本流程；后续逐算法迁移所有权。
- 当前历史恢复 XYZ 场景及本试点的显示属性；拟合基准、测量结果、RGB 派生结果和其关联关系未纳入完整历史恢复，不将本轮写成全项目完整撤销。
- 真实桌面验证为在已有桌面会话中发送 Qt 操作事件、渲染并核对截图；不等同于 Windows 人工操作验收。
- Windows 尚未验证。共有文件和历史接口已变化，其他功能若需回归，按项目规则先列明范围和耗时并征得用户同意。
- 本轮未改变测量结论或材料口径，既有凹塘/焊前专项 PPT 不更新。下一步用第二个简单编辑流程检验公共接口，再决定场景仓库与完整结果历史的推广方式。
