## 点拾取

将原两点测距交互提取、重命名为 Basic/ViewportPointPicker。空间距离仍调用 MeasureDistance，不改变计算定义。连续测距与一次性的单点/双点选择复用同一套鼠标事件、真实点吸附、屏幕坐标转换、标记、相机跟随与 GUI 生命周期。

- 测地线先选择输入点云与参数，再在指定点云上点击两个点；第二次点击后自动开始原异步计算。
- 圆柱弧长手动定位、曲率分割种子点一并迁移，才可安全删除旧 PointPicker / PointPickerMgr。
- 仅点击选点；拖动、拖回原位置、滚轮仍按原 VTK 交互处理。空白点不加入结果。
- 保留 Esc，提供明确的“取消”按钮。选点标记不参与拾取；临时点选模式不画直线距离，避免把弦长误当测地线。
- 完成/取消后移除临时标记，恢复光标与鼠标跟踪；不更换 VTK interactor、style 或其 picker。
- 选择完成通过回调衔接业务，没有旧类的嵌套事件循环和 30 秒超时。
- 切换操作、点云移除、窗口关闭会取消选择；已排队的完成回调核对当前操作版本及输入点云，避免对失效输入启动任务。
- 修正圆柱弧长位置对话框原先给错误 OptionBox 实例设置标题的问题。

## OOM 事故与防护

13:42 的内核记录确认 16 并发编译触发全局 OOM。首次 OOM 快照里 16 个 cc1plus 合计 RSS 19.18 GiB，而整机只有约 22 GiB；ChatGPT 与 code 进程被终止。这是本轮未先按内存调整并行度造成的失误。

原构建已结束；恢复时无编译进程残留，可用内存约 18 GiB。增加 analysis/run_guarded.sh：

- 独立 systemd 用户 scope，MemoryHigh=6 GiB、MemoryMax=8 GiB、MemorySwapMax=256 MiB；已读取实际 cgroup 文件验证对应字节值。
- 可用内存不足 10 GiB 时拒绝启动。
- 文件锁禁止同时启动多个受限构建/验证任务。
- 本轮全部后续构建、链接与显示验证在该范围内运行，编译并发降为 2。
- 四份既有 GUI 验证构建脚本与新拾取构建脚本都改为 2 并发，防止重用旧的 16 并发命令。
- 更新项目执行手册中的构建命令与事故说明；不修改依赖版本、CMakeLists、系统交换空间或桌面应用配置。
