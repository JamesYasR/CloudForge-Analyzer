# 架构评估与统一重构备忘

记录日期：2026-10-21。

## 当前决策

用户决定先继续完善小功能，采用增量更新；架构重构留到后续统一规划和实施。本备忘不构成本轮重构授权，不因完善某个功能扩大到全局改造。

## 评价基准

基于实际阅读及两点测距、多边形裁切开发中接触到的原有实现，按“能长期扩展的工程桌面软件”评价约 6/10。业务目录划分清楚，但模块边界、状态所有权和生命周期约束不足。此为局部代码审阅后的工程判断，未作全仓库正式审计；后续新增的交互控制器与验证程序不混入原始架构评分。

## 值得保留

1. 按拟合、测量、预处理、对话框等业务分目录，新增功能有明确归属。
2. 已有独立计算类的基础，例如接收点云、显式计算、读取结果的测量模块。
3. Qt Widgets / PCL / VTK 适合点云工程软件，不因技术栈成熟就判定落后。
4. 现有依赖精确锁定、统一 CMake、GUI/计算线程分工及基线验证纪律应保留；这些是逐步建立的工程能力。
5. 撤销使用共享指针保存点云快照，避免每步复制大点云，思路实用。

## 主要结构问题

| 问题 | 已见证据与影响 | 后续方向 |
|---|---|---|
| 主窗口职责过多 | `Src/CloudForgeAnalyzer.cpp` 约 4700 行，集中处理界面、数据、算法编排、绘图、报告、任务与撤销；局部功能改动需理解多种状态 | 逐步提取功能控制器，主窗口负责装配与入口 |
| 场景状态分散 | CloudMap、ColorMap、RGBCloudMap、ActorMap、拟合结果池及 PCL actor 表共同描述场景；清理一致性依赖各调用入口 | 建立统一场景对象记录，集中维护增删、属性和关联结果 |
| 类的职责边界不稳定 | 旧拟合类持有参数对话框；PointPickerMgr 构造时启动选点并进入局部事件循环 | 参数收集、显式计算、交互生命周期分开；创建对象不隐式开启长流程 |
| 撤销记录不完整 | 快照主要覆盖点云与颜色，变换、显示属性、拟合结果和标注缺少统一保存；保存时机与批次配对依赖调用者 | 定义操作事务和恢复范围，逐步约束接口使其不易用错 |
| 参数传递脆弱 | 部分参数以字符串数组及下标传递，新增字段容易错位 | 使用具名、具类型的参数结构，统一校验和默认值 |
| 编译依赖范围过大 | 主窗口头文件汇总包含大量算法、Qt、VTK 头文件 | 减少汇总包含、增加前置声明，形成可独立构建测试的模块边界 |

补充：测距开发曾因提前访问 VTK 相机引入默认视角变化，这是本次开发者引入的错误，不能归责于原实现；同时说明视窗初始化存在隐含规则，后续应在集中管理层内加以保护。

## 后续统一重构的建议顺序（尚未启动）

1. 统一场景对象与状态所有权：点云、颜色、变换、可见性、关联结果采用清楚的数据记录与更新入口。
2. 统一交互工具生命周期：进入、进行中、完成、取消与清理；测距、裁切、选点各自管理状态。
3. 统一算法输入输出：参数结构、结果结构、显式计算、进度及取消约定。
4. 在上述边界稳定后整理主窗口、撤销恢复范围与模块测试入口。

重构前先固定各功能行为与验证基线，按模块迁移，保留可回退节点；不为追求文件数量或设计模式进行大范围改写。
