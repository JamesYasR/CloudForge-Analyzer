## 二、本次会话解决的问题（8 类，均邮件通知）

### 1. boost 1.86.0 下载失败（curl 56 SSL 中断）
- **现象**：`github.com/boostorg/boost/archive/boost-1.86.0.tar.gz` 下载 SSL unexpected EOF
- **处理**：从 portfile 拿到 URL+SHA512，改用 `codeload.github.com` 手动下载，SHA512 校验通过
- **产物**：`vcpkg/downloads/boostorg-boost-boost-1.86.0.tar.gz`

### 2. boost 84 个子包批量下载失败
- **现象**：github.com archive 域名不稳定，多个子包下载中断
- **处理**：写脚本遍历所有 boost 端口 portfile，提取 REPO/REF/SHA512，全部改用 codeload 预下载；19 个失败包用 wget 重试全部成功（65+19=84 个）
- **教训**：github.com/archive 下载不可靠，codeload.github.com 稳定

### 3. 系统 OOM 重启（重大）
- **现象**：22:07 内核 OOM killer 杀掉 VS Code 等桌面进程，22:24 系统重启
- **根因**：22GB 内存 + **无 swap** + vcpkg 并发语义是"同时 16 端口 × 每端口 16 并行"= 最多 256 个编译进程，PCL+boost 同编内存爆掉。`taskset -c 0-15` 只限 CPU 亲和，不限内存
- **处理**：用户手动创建 16G swap（`/swap.img` 已挂载）；并发恢复 16 线程
- **结论**：swap + 16 线程并发后未再出现 OOM

### 4. PCL 1.14.0 ply_parser.h GCC 15 兼容错误
- **现象**：`list_property_begin_callback_type<unsigned int, double>` 无 `type` 成员（第 513-516 行），还缺 `#include <functional>`
- **处理**：创建 `vcpkg-ports/pcl/` overlay port（复制 vcpkg versioning 端口 + 新补丁 `fix-ply-parser-gcc15.patch`），局部别名改名避免遮蔽 + 补 functional 头

### 5. PCL sha1 API 与 boost 1.86 不兼容
- **现象**：`pcl_visualizer.cpp:4594` 用 `unsigned int digest[5]` 调 boost 1.86 的 `get_digest`（要求 `unsigned char[20]`）
- **处理**：`fix-sha1-boost186.patch`，改用 `unsigned char digest[20]` 逐字节输出 hex

### 6. PCL FeatureContainer::getClassName 不存在
- **现象**：`correspondence_rejection_features.h:274` 嵌套类误调外层实例方法
- **处理**：按上游 master 做法，`fix-getclassname.patch` 硬编码字符串

### 7. PCL poisson4 库 GCC 15 模板错误
- **现象**：`sparse_matrix.hpp` 的 `m_N/m_M/Min/Rows/Columns` 不存在；`octree_poisson.hpp` 的 `offset` 应为 `off`
- **处理**：`fix-poisson4-gcc15.patch`，按上游 master 修复（SetZero 重写、`std::min(rows, _maxEntriesPerRow)`、`bb.Dimensions()`、`off` 改名、补 `<algorithm>`）

### 8. 项目源码 Windows→Linux 大小写问题
- **现象**：Windows 下文件名不区分大小写，Linux 严格区分导致 include 找不到
- **已修复**：

  - `Inc/Dialog/headers.h` `#include <QDIR>` / `<QFILEDIALOG>` → `QDir` / `QFileDialog`

  - `Inc/Linear_Depression_Plane.h:13`、`Inc/Protrusion_Depression_Cylinder.h:13` `#include <Boost/...>` → 小写 `boost`

## 五·一、多线程并行（OpenMP）双平台兼容修复记录（2026-08-24）

### 问题
运行时报：`[pcl::NormalEstimationOMP::setNumberOfThreads] Parallelization is requested, but OpenMP is not available!`

### 根因
vcpkg PCL overlay portfile 里 `-DWITH_OPENMP=OFF`——PCL 库本身以无 OpenMP 方式编译，所有 `*_OMP` 类和 `#pragma omp` 内部实现退化为串行。

### 修复
| 项 | 修改 | 双平台说明 |
| --- | --- | --- |
| PCL 编译开关 | `vcpkg-ports/pcl/portfile.cmake`：`-DWITH_OPENMP=OFF` → `ON` | MSVC 与 GCC 下 PCL 的 WITH_OPENMP 均为标准 CMake 选项，Windows 重建时同样生效 |
| 项目 CMake | 已正确 `find_package(OpenMP REQUIRED CXX)` + 链接 `OpenMP::OpenMP_CXX`（原有，无需改） | MSVC 自动加 `/openmp`，GCC 自动加 `-fopenmp` |
| `<omp.h>` 规范化 | `Src/CloudForgeAnalyzer.cpp` 补 `#include <omp.h>`（原缺失） | 双平台都应显式包含 |
| rand() 线程安全 | `Src/CloudForgeAnalyzer.cpp` 并行采样循环内 `rand()` → 线程私有 `std::mt19937`（以 `random_device ^ omp_get_thread_num()` 播种） | `rand()` 保持全局共享状态，MSVC/GCC 下并行调用都有数据竞争 |
| Cluster.cpp 颜色 | 已用确定性颜色 `(cluster_id*k)%256`，无需改 | 作者原处理已线程安全 |

### 覆盖的并行点（8 个源文件，21 处 #pragma omp）
- `Src/CloudForgeAnalyzer.cpp`（parallel/for nowait/critical + 线程私有 RNG）
- `Src/Measure/MeasurePlanarity.cpp`（parallel for + reduction min/max）
- `Src/Measure/MeasureWeldHeight.cpp`、`MeasureCylindricity.cpp`（parallel for + reduction）
- `Src/Fitting/Fit_Cylinder.cpp`（NormalEstimationOMP + parallel/critical）、`Fit_Line.cpp`（omp_get_max_threads 分片）
- `Src/PreProcessing/Cluster.cpp`、`ProtrusionSegmentation.cpp`（omp_get_thread_num 分片 + critical）

### 验证结果
- PCL 重建参数确认：`-DWITH_OPENMP=ON` + `-fopenmp`（config 日志可见）
- 静态库符号：libpcl_filters 79 个、libpcl_features 641 个、libpcl_registration 49 个 OpenMP 符号
- 可执行文件链接 `libgomp.so.1`
- 运行验证：应用启动稳定，**OpenMP is not available 警告消失（0 条）**

## 六、经验教训

1. **下载**：github.com/archive 不稳定，优先 codeload.github.com；失败用 wget 兜底
2. **OOM**：vcpkg 的 `VCPKG_MAX_CONCURRENCY` 是"同时端口数"，需配合 swap；taskset 不能防 OOM
3. **GCC 15 兼容**：PCL 1.14.0 有多个 GCC 15 严格检查问题（模板遮蔽、缺头文件、two-phase lookup），都按 PCL 上游 master 的修复方式打补丁
4. **Windows→Linux 移植**：源码中 Qt/boost 头文件大小写必须修正
