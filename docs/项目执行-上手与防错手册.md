## 2. 硬红线（违反会造成不可逆或难排查的问题）

| # | 禁止 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 升级/降级依赖 | 双平台直接崩 | Qt 6.7.3 / PCL 1.14.0 / VTK 9.3.0 **精确锁定**，要动先协调 |
| 2 | 改 `CMakeLists.txt` | 违反项目铁律 | 新增 `.cpp/.h` **无需**改（GLOB 自动收集）；测试程序放 `analysis/` 不进 CMake |
| 3 | 重建 `.sln/.vcxproj` | 已废弃 | 只用 `CMakeLists.txt` |
| 4 | 清理"未跟踪文件" | 丢别人的工作 | 只动你明确要改的文件；`git status` 只应出现预期改动 |
| 5 | 在计算类里弹 Qt 对话框 | 线程/架构崩坏 | 计算类不依赖 Qt；参数由 `ParamDialog_*` 收，构造 + `compute()/evaluate()` 传入 |
| 6 | 在 worker 线程碰 VTK/Qt/查看器/点云表/撤销 | 随机崩溃 | 只在 GUI 线程；worker 用 `PostProgress/PostLog`，结果用 `shared_ptr` 回传 |
| 7 | `pkill -f "build/CloudForgeAnalyzer"` | **杀掉自己所在的 shell** | `pkill -x CloudForgeAnalyze`（进程名被截断为 15 字符） |
| 8 | 改了头文件却直接链接旧测试 .o | ABI 不一致 → 读出全 0/垃圾/崩溃 | 用 `build_test.sh`（它先 `ninja` 再编译测试 .o） |
| 9 | 改参数对话框时插在中间 | 既有功能参数错位（索引敏感） | 新参数**只能追加在末尾**；默认值改一处要同步三处（见 §5.3） |
| 10 | 用 `sed -i` 批量改代码后不编译 | 曾留下重复/孤立代码 | 改完必须编译 + 读回改动处确认 |

## 4. 代码风格速查（照抄现有写法，别发明）

- 类名：`MeasureXxx` / `Fit_Xxx` / `Filter_xxx` / `ParamDialog_Xxx`
- **可测性套路**：`Xxx(cloud, params)` 构造 + 公开 `compute()/evaluate()`；**不在计算类里弹框**（旧构造保留兼容）
- 结果：`XxxResult` 结构体返回；进度：`setProgressCallback(...)`；GUI 侧传 `WorkerProgressCallback()`
- 异步：`RunAsyncVoid(title, work, onFinished)`；取消：`IsTaskRunning()` / `CancelCurrentTask()`
- 日志：调试走 `TeEDebug()`、线程安全日志走 `PostLog()`、报告弹窗走 `Update_CFmes(text)`；**不要 `std::cout`**
- 文案：界面与报告用中文；**客户可见文本禁止出现"口径A/口径B"**，统一说"局部基准 / 到理想柱面距离"
- 注释：解释"为什么这么做"（现有代码注释风格偏详细，含实测数字），不要写"这里加 1"式废话
- 变量命名：跟现有文件保持一致（成员尾部 `_`，如 `design_radius_`）

## 5. 验证规矩（"我说改好了"必须附证据）

### 5.1 改完必做四件事

1. **构建 0 error**（贴最后 3 行）
2. **算法改动 → 跑无界面验证并对照基线**（见 5.2）；**没跑就等于没验证**
3. **动 UI/可视化 → 在桌面会话里实际点一遍**（列出你点了什么、看到什么）；不需要图形环境就能验的，优先用 harness
4. **同步文档**：设计文档（`docs/当前需新增功能/*.md`）与对外材料（PPT 源在 `analysis/ppt/`）

### 5.2 基线对照（算法改动的唯一可信证据）

```bash
D=analysis/cylinder_patch/out_multipit
./build/test_cyl_pothole PCDfiles/pothole_dent_form.pcd 1940 local=1 win=90 lthr=0.35 \
   minpts=60 ctol=5 axis=$D/axis_form.txt > /tmp/new.txt 2>&1    # /tmp 本次调用内有效即可
diff <(grep "^\[KEY\]\|^\[PIT\]" $D/v9_final.txt) <(grep "^\[KEY\]\|^\[PIT\]" /tmp/new.txt)
```

- **逐位一致** → 说明只改了输出/UI，没动算法（本次报告精简就是这样证明的）
- **有差异** → 必须在汇报里逐个数字解释原因，并说明是否符合预期

### 5.3 三个样本的期望值（回归清单）

| 样本 | 命令要点 | 期望 |
|---|---|---|
| `PCDfiles/pothole_dent_form.pcd`（2M，含形面偏差+4 真值坑） | `local=1 win=90 lthr=0.35 minpts=60 ctol=5 axis=$D/axis_form.txt` | `[PITCOUNT] 4`、4/4 通过、最深 1.549 mm |
| `PCDfiles/pothole_test.pcd`（理想单坑） | `local=1 win=90 axis=$D/axis_test.txt` | `[PITCOUNT] 1`、1/1 |
| `test2/1_cld.pcd`（真实，350 万点，外接盘） | `local=1 win=90 axis=$D/axis_1cld.txt` | `[PITCOUNT] 9`、**3 通过**（该结论待甲方确认，见 §8） |

## 6. 坑表（症状 → 原因 → 正确做法）

| 症状 | 原因 | 正确做法 |
|---|---|---|
| PCD 读出来是"假共线"点云 | `binary_compressed` 解压后是 **SoA/planar** 布局，按 AoS 读错位 | 按字段分别 reshape：`np.asarray(col).reshape(npoints)`（参考 `analysis/cylinder_patch/analyze_cylinder_patch.py`） |
| 测试程序读出全 0 / 崩溃 / 轴向量是垃圾 | 改头文件后测试 `.o` 未重编，ABI 不一致 | 一定用 `build_test.sh`（内部先 `ninja` 同步工程 .o） |
| 构建报 `vcpkg install failed / Read-only file system` | vcpkg 根在沙箱外 | `build/CMakeCache.txt` 里已设 `VCPKG_MANIFEST_INSTALL:BOOL=OFF`，不要打开 |
| 跨 bash 调用的临时文件不见了 | 每次调用 `/tmp` 独立 | 临时文件放工作区内（如 `analysis/cylinder_patch/out_*/`） |
| 关闭窗口后 CPU 仍 100% | `xkill` 只关窗不杀进程，成孤儿进程 | 用 `pkill -x CloudForgeAnalyze`；启动用 `setsid nohup ... & disown` |
| 应用黑屏 / 窗口不出现 | 无 `/dev/dri` 或窗口被 Iconic；也曾因 `xkill` 搞坏 mutter | 在**桌面会话**里跑；Wayland 下用 `QT_QPA_PLATFORM=xcb`；必要时让用户重新登录 |
| 编译特别慢 | Debug 构建（约 Release 10 倍） | `analysis/run_guarded.sh taskset -c 0-3 cmake --build build --parallel 2`；单次构建，内存上限 8 GiB |
| 计时结果异常 / 机器卡 | 有孤儿进程或在跑别的重活 | 先 `ps -eo pid,comm,args \| grep -i cloud` 清干净再测 |
| 椭圆拟合结果乱（长短轴/角度错） | Halir-Flusser 三个坑：约束缩放、特征向量符号、长轴角需 +π/2 | 已修，见 `MeasurePothole.cpp`；改椭圆务必保留符号判别 |
| worker lambda 里用 `Ptr&` 构造报错/空指针 | 引用绑定临时对象 | 在 worker 内先声明局部左值再传引用 |
| lambda 里调成员函数编译错 | 漏了 `this` 捕获 | 捕获列表补 `this` |
| VTK 3D 文字看不见 | PCL `addText3D` 的 `textScale` 是**世界单位(mm)**，不是像素 | 按场景取：`clamp(2.2% × 包围盒对角线, 6, 14) mm`（见 §8 输出规范） |
| `getMinMax3D` 编译失败 | 输出点类型与点云点类型不一致（XYZ vs XYZRGB） | 输出变量用同类型（`pcl::PointXYZRGB lo, hi`） |
| 引线/线宽不生效 | 线宽要单独设渲染属性 | `setShapeRenderingProperties(PCL_VISUALIZER_LINE_WIDTH, w, id)` |

## 6.4 构建资源保护（2026-10-22）

当前开发机约 22 GiB 内存。曾因 16 并发编译触发 OOM，单次快照中 16 个 cc1plus 合计 RSS 19.18 GiB，桌面应用被系统终止。后续 agent 不得直接沿用旧的 16 并发命令：最多 2 个编译任务，使用 `analysis/run_guarded.sh` 将整段构建/验证命令放进独立的 8 GiB 内存限制；系统可用内存不足 10 GiB 时拒绝启动。构建脚本中仍有历史 16 并发写法的，执行前先降到 2。不得同时发起多个重编译或链接。

## 6.5 跨功能回归：**必须先征得用户同意**

改动落在共享文件（`Src/CloudForgeAnalyzer.cpp`、`CloudForgeAnalyzer.ui`、`Inc/CloudForgeAnalyzer.h`、
`Inc/Measure/Measure.h` 等）时，其他功能在编译/链接层面同属"爆炸半径"。规则：

- **允许**：跑**本功能自己**的验证程序（如焊前的 `analysis/weld_preparation/build_test.sh`）。
- **必须先问**：跑**其它功能**的验证程序或与其它功能基线做比对（哪怕只是只读运行）。
  用户明确要求："之后不要随便跑功能回归，如果有这个必要征求我的同意。"
- 征询话术：说明"改了什么共享文件 → 担心影响哪个功能 → 建议跑哪个验证 → 预计耗时"，得到同意再跑。

## 8. 当前"不要动"的区域（决策未定，动了会白做）

1. **真实样本 `1_cld` 的结论**：现在跑出"9 候选 / 3 通过（5~24 mm，深 0.8~1.2 mm）"，
   而旧文档/PPT 写的是"不判定"——**待甲方判断这 3 处性质**，在定论前不要改判定逻辑或对外材料口径。
2. **局部阈值默认值 0.35 mm**：为检出 0.5 mm 浅坑而定，**未经甲方确认**；要改必须同步 §5.3 的三处并在汇报里说明影响。
3. **椭圆长短轴偏小 4%~32%**：验收口径（阈值轮廓 vs 真实足迹）未定，不要私自加经验补偿系数。
4. **对外材料口径**：PPT 第 10 页那条"真阴性"说法与 §8.1 冲突，等结论确定后一并修正（源在 `analysis/ppt/build_deck.py`）。
5. **1.3/1.4 的口径已由用户拍板（2026-09-27），不要自行改动**：阶差 = **径向** `e_P − e_Q`（近件在外为正）；
   间隙 = **跨缝方向开口**（本批环缝 → 轴向）；两量由**同一次配对**同时给出；**入口已合并为一个**、
   **三维可视化已删除**、报告为精简格式。详见《焊前装配阶差与间隙-独立执行方案》§0 口径变更记录。
6. **依赖版本 / CMakeLists / Windows 预设**：见 §2 红线。
